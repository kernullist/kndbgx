# KNDbgX implementation design

This document describes the extension architecture, execution boundaries and resource ownership. Operator controls are documented in [UX.md](docs/UX.md), and build and test procedures in [VALIDATION.md](docs/VALIDATION.md).

CLI, embedded WebView2 and optional host Data Model views share the command registry, application coordinator and immutable result model. DbgEng sessions access the target only from their owning thread. The implementation is x64-first; results identify unsupported architectures and unknown layouts.

## Execution and lifetime

A CLI invocation binds a callback-local debug client. The worker creates, uses and releases its own client on the worker thread. Regular methods check the owning thread before entering DbgEng. One execution lease per logical session prevents concurrent target work. A reserved job becomes runnable after the CLI has printed its job ID, avoiding output calls while an opaque engine command owns execution.

Cancellation uses a separate serial-scoped control path and documented DbgEng interrupt access. It does not wait on the execution lease. Acknowledging cancellation does not promise that a blocked engine operation has returned. Jobs retain status and bounded output; the common result store owns finalized data.

Windows, queued work and callbacks hold module leases. Shutdown closes admission, signals cancellation, drains work and releases engine objects on their owner thread before the DLL lease ends. UI navigation generations reject queued responses for a previous page/window. Closing an idle UI does not interrupt the target.

Session stamps contain session identity and target, stop, context and symbol generations. Reconnect, resume, external context changes and symbol changes invalidate dependent state. Internal CPU/context traversal uses a guard that restores saved context and faults the session if restoration fails. Restore attempts check target, stop, context and symbol generations before and between groups, refusing stale restoration after an external change.

## Command effects and approval

`src/cmd/CommandSpec.cpp` is the authority for names, aliases, argument counts/options, effects, capabilities, kernel session modes, support and handlers. The parser consumes the full typed input. Registered commands keep strict validation on every surface. CLI and jobs refuse unknown verbs and opaque trailing syntax; `raw --ack-effects` is their separately acknowledged opaque operation. There is no global write policy; legacy `policy` / `gate` CLI names remain registered solely to report removal instead of falling through to WinDbg. Kernel session modes distinguish kernel dump from live kernel availability; the dispatcher refuses commands outside the current mode with an explicit session-mode message, and registered mutation or execution-control commands are always live-only.

Manual UI input uses `ParseUiCommand` during classification and `CommandInput::UiConsole` during dispatch. Registered names and aliases take precedence even when their arguments are malformed. Other input uses an engine-only `OpaqueEngine` handler outside the registry, preserving the original string for `ExecuteWide` rather than applying KNDbgX quoting or option rules. It retains text output with `windbg` provenance and `UnverifiedEffects`, invalidates target epochs, and clears both memory and debugger-action approvals before and after execution. Owner-thread, execution-lease, cancellation, fault containment and result-retention handling remain shared with registered commands. Bound memory/navigation actions continue using registered dispatch.

WinDbg result metadata stores the original input in `analysis.hostCommandLine`; result-info replies project it as `command` without duplicating it in metadata. Execution receipts carry the post-command `currentTarget`, including bounded completion records. The frontend adopts it before accepting another command and invalidates older status queries. Reopening a saved result does not change the current target.

Memory plans preserve exact original/desired bytes and bounded ranges, UTC/steady expiry, PDB field identity where applicable, a session stamp and a CNG-generated token. Approval consumes the matching plan, checks generations, rereads original state, and writes/verifies bounded chunks. Only that scoped execution grants the engine's internal write permit; ordinary direct writes remain refused. Partial failure reports applied/unapplied/verified ranges without hidden retries. Physical writes and unsupported typed fields cannot fall through to a second implementation.

Debug actions have their own plan store. Existing breakpoints are bound to GUID and observed settings so an engine-reused numeric ID cannot authorize a different breakpoint. Breakpoint pointers returned by DbgEng creation and lookup methods are borrowed; removal invalidates them. A separate interface reference acquired through `QueryInterface` must be released and is held in `ComPtr`. Go/step calls use typed execution status.

The UI's `breakpointPlan` and `breakpointApply` RPCs run on the owned engine worker and reuse `debug-plan` / `debug-approve`. Enable/Disable prepares and consumes a bound one-use plan from the user's click without an approval dialog; Add/Delete still waits for explicit preview approval. List actions resolve an immutable result row and recheck its GUID/configuration against DbgEng; instruction additions resolve the captured `u` row's address. Manual Add accepts one bounded expression. Planning and approval require a complete current stamp, observation support and a stopped live target; dumps and local kernel sessions are refused. Code additions check for duplicates at both stages. `discardPlan` clears matching memory or debugger-action plans; lifecycle/context invalidation still discards pending changes. Global `gate` / `setGate` RPCs and `gateOpen` metadata are removed.

The breakpoint table renders its boolean state and row toggle together in the Enabled cell without changing stored records or sort/copy values. Rendered controls bind their result revision, row identity and current inventory index; detached controls cannot act after sorting, virtualization or result replacement. Existing toolbar and row controls share the same status/context checks and native planning/application path. The state column has a 160-pixel minimum so its label and action stay visible within the fixed-height row.

The session stamp also carries optional engine IDs, implicit process/thread offsets, effective architecture and scope coordinates. A separate owner-thread client observes engine callbacks throughout extension lifetime. Incomplete context or unavailable observation refuses sensitive actions. Internal context guards require complete capture before switching and report capture/restore masks.

## Results and collected data

`kndbgx.result.v2` carries status, native error, data source, consistency, layout source, target stamp, rows, findings, limitations and coverage. Status is one of Success, Partial, Unavailable, Unsupported, InvalidInput, Cancelled, StaleContext, EngineError, IOError or InternalFault. Unknown scalar fields are null. Addresses, identities, generations and exact 64-bit counters use strings in JSON.

Exact reads never zero-fill missing bytes. Sparse reads retain holes. Walkers share cycle detection, cancellation and global budgets. Default list traversal is bounded to 65,536 nodes / 5 seconds. Process inventory uses 30 seconds; minifilter traversal uses one shared 60-second deadline after layout/ownership setup, with entry/row caps, operation end markers and cancellation retained. Slow native reads can outlast a cooperative deadline. Ownership of an address is Unknown for incomplete or overlapping module ranges. Coverage distinguishes visited/read/decoded/classified/unknown/unreadable entries and complete versus stopped collection.

The result store keeps immutable results, allowing 16 unpinned recent entries and up to 128 protected open UI tabs within a shared 64 MiB budget. UI and CLI resolve the same result ID. The worker's job record keeps metadata, result ID and up to 512 KiB of formatted text. The UI uses 128-row pages, 4,096-unit console chunks, a 64 KiB RPC response limit and a 262,144-unit visible console limit. Rows and findings have independent pages and counts. Oversized records produce stable export references and advance the cursor. Page budgets count UTF-8 JSON-array bytes, including delimiters. Data Model creates an explicit page of values copied into host memory and installs no extension-owned property callbacks.

## Layout and collectors

PDB identity is verified against image GUID/age and target machine before type data is accepted. DIA supplies scalar widths, signedness, array dimensions and bitfield positions; cached layouts are generation scoped. Offset zero is valid. Missing metadata is not replaced with a neighboring offset or a guessed stride.

Process, VAD, handle, object and driver collectors preserve partial-field and enumeration failures. PID reuse and duplicate selectors are not silently resolved. Host handle/Toolhelp/firmware/WFP data are labeled as collected from the host. Cross-view differences require successful complete enumerations before an absence candidate is emitted.

Scanners separate observations from conclusions. CR4 SMEP/SMAP use bits 20/21; MSR differences do not imply hooks. DPC uses verified singly linked topology. Timer extents use PDB arrays; encoded DPC pointers are not guessed. Minifilter collection follows matching `_GLOBALS`, `_FLTP_FRAME` and `_FLT_FILTER` metadata and never writes callbacks. Missing NMI/ETW/CI/unloaded/firmware private layouts yield explicit gaps.

Callback collection prefers matched PDB metadata for notify arrays and object entries. Exact-identity fallbacks in `profiles/nt-26100.8655-callbacks-x64.json` and `profiles/nt-28000.2952-callbacks-x64.json` record reviewed allocation, iteration and field-store code. The compiled profiles check PDB GUID/age, machine, image timestamp/size, symbol RVAs and required code windows in the target before filling missing fields. Existing contradictory metadata is never replaced. Registry enumeration requires a verified profile and corroborates list length against the kernel's count. A missing or changed code window refuses the fallback; these checks establish layout compatibility, not whole-image integrity.

Result annotation reuses reverse symbol bindings, including failures, by module base and qualified name within one result. Each row still validates the requested address and displacement. The cache does not cross result boundaries or bypass the shared DbgEng execution lock.

Object callbacks retain paired Pre/Post pointers, symbols and ownership in one registration row. Coverage gaps, table extents and raw-slot probes live in `analysis.diagnostics` and console output rather than empty observation rows. Shared address annotation requests the owning module's deferred symbols through DbgEng and verifies the name/displacement against the requested address before retaining it. Missing or rejected names use an explicit module/RVA fallback where ownership is unique. Minifilter operation rows retain numeric `major` plus derived `majorName`; the UI uses the label for display/sorting/cell copies, while snapshot comparison ignores the derived label.

`profiles/nt-26100.8655-x64.json` records the image and symbols used to verify the native service table. Its image entries are disk RVAs; runtime signed-relative entries require a separate decoder. `tools/verify-profile.py` verifies image/PDB hashes, public symbol RVAs, extent and executable disk RVAs. It explicitly does not establish runtime kernel-memory support.

## Files and snapshots

The October 28 reference update adds an `unloaded-drivers` collection to snapshot v2 (collectorVersion 3).
Its session-local event key requires verified name, address range and nonzero unload time. Ring slot/cursor/storage
addresses are excluded from value comparison. Repeated loads at reused bases remain separate events; incomplete,
duplicate, old missing-collection and cross-session inputs retain Unknown/Partial semantics.
The comparison checks row identities independently of imported coverage metadata. An unidentified row prevents
Added/Removed claims for that collection, while comparisons of matched known rows remain usable.

Artifact creation uses same-directory temporary files, exact writes, flush/close checks and non-overwriting rename. Faults preserve pre-existing files. JSONL has a completion footer. SHA-256 is valid only after normal EOF; cancellation, budgets, mid-read errors and detectable concurrent changes return no digest.

Snapshot v2 uses new directories, bounded manifests/rows/files, checksums and schema checks. Paths reject traversal, alternate streams and reparse traversal. Stable identities and module-relative addresses support order/ASLR-independent comparisons. Duplicate identities, incomplete sides, schema mismatch and missing imported fields remain incomparable/Unknown. Cross-session comparison is explicit.

Snapshot comparisons retain source status, coverage, errors and limitations in `analysis.inputCollections`. Finished comparison and complete input coverage are separate flags. Confirmed field differences survive unrelated null fields.

Saved-result v3 streams JSON values with incremental hashes and a completion object before atomic commit. UI Export and offline `result-export` share this path; it supports every admitted result without building the entire serialized response in memory.

Export failures retain the destination and Win32 error. Disk-full errors include a recovery command for the original retained result; diagnostics do not retry publication or change the source result.

Artifact writers poll cancellation between 64 KiB writes and after flush/close before rename. Snapshot collectors pass cancellation through file writes, hashing and final directory publication. Successful rename is the publication boundary; a later cancel does not retroactively hide a published artifact.

## UI communication

Header Continue/Break uses the existing bound execution path and observer interrupt endpoint. Break is independent of command cancellation and a delayed Continue completion receipt. Status polling continues during pending execution controls; a newer stop cannot be replaced by an older receipt. An accepted interrupt remains pending until fresh status confirms the stop. Unsupported/dump/local-KD states refuse execution controls.

Command history retains 200 entries and tracks the recalled text separately from its shifting index. Toolbar commands preserve the draft, selection and unresolved argument fields even when history evicts the recalled entry. Memory/Disassembly completion overlays do not change read-button layout. Inspector width is a separate bounded browser preference from the shared Inspect panel.

Ordinary `WM_CLOSE` hides the native window and WebView2 controller while retaining the document, result-tab objects and result-store protection. `!kndbgx` shows that same workspace; explicit shutdown and extension unload destroy it. Visibility intent also applies during asynchronous controller creation. Failed visibility changes invalidate the document through the existing `Visible` failure stage, with explicit retry and no command replay. Document recreation releases its tab state. While hidden, periodic status and automatic target reads pause. Reopening invalidates checked execution state; command input, process actions, Memory/Disassembly reads and Inspector target actions require fresh status before access.

The catalog carries the compiled registry's grammar alongside each name, alias, summary and support label. Library search, the palette and input hints use this metadata. Library group folding and Recommended/Name sorting persist independently of the current filter. Name completion and required-parameter templates are local; argument completion uses the read-only `complete` RPC for help operands, process selector prefixes and registered options. Templates track unresolved fields and prevent submission until they are filled. `help ui` is shared by CLI and the UI's `:help` shorthand.

Command, Memory and Disassembly inputs share an owner-aware `completeSymbols` queue on the engine worker. Lookup uses already loaded symbols, requires a stopped current context and never reloads symbols, evaluates the input expression or submits a command. Only one frontend lookup is pending and the newest queued prefix replaces older queued work. The 180 ms debounce, 24-entry limit, eight-module unqualified search and cooperative 200 ms engine budget bound optional work; an individual engine call can outlast that budget. The frontend expires optional lookup after eight seconds and acknowledges late terminal receipts without presenting stale suggestions. Input revision, focus, caret, composition and target-stamp checks reject obsolete results. Physical-address inputs do not offer virtual-symbol completion. Required grammar remains available after optional lookup failure.

RPC v3 binds derived navigation to a source result ID, collection, index and complete expected stamp. The owner worker resolves immutable stored data and revalidates immediately before access. Manual commands deliberately use current context.

Callback navigation adds an explicit field to that source binding: `routine` for `RoutineObservation`, or `preRoutine`/`postRoutine` for `ObjectCallbackRegistration`. Native resolution validates the field against the stored record kind, rejects zero/unavailable callbacks and treats callback code as virtual memory. Both `memoryRead` and `disassemblyRead` resolve bound fields before dispatch instead of trusting the input expression. An empty source retains manual-input behavior. The Inspector selector and address-cell context menu preserve immutable indexes through sorting and tab restoration, and reads leave the main result selected.

Other result addresses use an explicit `path` array in the same binding. A shared native policy projects `addressFields` beside each UI result page and resolves the selected path again from the immutable source at dispatch. The UI retains this projection in a WeakMap rather than modifying records or exported data. Recognized pointer/range fields, instruction/stack registers, expression values and nested object fields have virtual/physical semantics; hexadecimal flags, offsets, timestamps, RVAs and arbitrary strings are not inferred as addresses. PA/DTB fields remain physical, and nested fields inherit an explicit address space unless the field defines its own. File spaces, imported file provenance, snapshot differences and historical nested records do not borrow the current target. User pointers associated with a process require that process to be attached; unknown owners are refused. On x86, the entire 32-bit range receives this check, including possible high user mappings. Projection is bounded to 32 fields, four path components and 512 visited fields per record. The UI page's 24,000-byte record budget and 24,000-byte address-metadata budget are separate; pages shrink their record count when needed to stay within the RPC wire limit. Legacy address and callback bindings resolve through the same projection and ownership checks; typed callback routines remain virtual. Existing Inspector actions use the same availability checks as address menus.

Memory and Disassembly address-cell menus use the same native path binding to cross-open the other view. The frontend binds each action to the captured snapshot object, original result ID, row index, address field and full stamp, independently of the main Results selection. Replacing the snapshot or leaving its visible inspection tab invalidates the menu binding. Memory row indexes follow the stored 16-byte rows, regardless of display width; Disassembly uses original instruction indexes. Physical Memory cannot open Disassembly, and decoded instructions open Virtual Memory. Byte/ASCII/instruction-text cells remain copy-only. Expired source results fail without manual-input fallback. Module/RVA display labels omit a zero offset while retaining raw values and nonzero offsets; module inventory still avoids eager PDB loading.

Processes, Memory, Disassembly and Registers share one resizable right panel. First use shows Memory; panel preferences restore visibility, selected tab and preferred width. Captured views remain document-local. Registers uses the existing `registers` collector and bounded result paging through the shared coordinator without selecting a Results tab. Visible register views refresh once per stopped target stamp; cancellation, invalid pages and context changes retain the previous capture. Integer values and raw vector bytes remain exact strings, unavailable values remain unknown, and change highlighting compares the same session and thread/CPU across captures. Replacing or filtering register rows dismisses their copy menu without interrupting a menu from another view. Result sorting loads the displayed collection's remaining pages, keeps exact integer/address comparisons and maps selection/actions back to immutable source indexes. Column widths and sort/layout state are separate for Rows/Findings; bounded per-document retention does not modify the stored result or export order. Dismissing a notice changes presentation only and preserves stale-address restrictions.

Memory and Disassembly each retain at most 20 completed manual address expressions in the versioned `kndbgx.address-history` WebView-profile setting. Memory records the address space; neither list stores captured data or target bindings. Loading rejects malformed, unsupported or oversized settings and validates/deduplicates bounded expressions. Selecting Recent explicitly reads the expression against the current stopped context and current read size, with the normal request gates; loading settings never starts a read. Automatic Follow IP and breakpoint-maintenance decoding do not record entries. Storage failure leaves current-document history usable. These persisted input lists are separate from document-local captured views and KNDbgX's `history`/bookmark navigation that retains original result stamps.

Command input remains locked for running/EngineBusy targets and while execution state is unknown. A valid stopped or explicit no-target status restores input without submitting the draft. Busy/unavailable observations invalidate in-flight preparation even if a later status is stopped. Breakpoint previews also compare the full context before presentation and approval. An applied instruction change refreshes the list and decoded range only while cancellation, the captured range, the active tab and the applied context allow it; an intervening Busy state or failed list refresh suppresses automatic decoding. Stop during stored page delivery does not interrupt completed engine work.

Worker operations use a host-owned key `(window generation, document generation, request ID)` and a separate operation ID. Cancellation flags belong to the work item. Engine cancellation uses the execution serial captured immediately after acquiring its lease. A bounded ledger records completion responses before transport, independently tracks posting/acknowledgement, and exposes read-only `operationStatus` and `operations`, plus idempotent `operationAck`. Status queries never reexecute a command. Completion records cap metadata at 64K UTF-16 units and refer to the stored result when more detail is needed. There are at most 128 records; completed records expire after 30 minutes and acknowledged records can be evicted under pressure. Active work is never evicted, and admission applies backpressure when unacknowledged records fill the ledger. The ledger is in memory and ends at DLL unload.

The UI monitors every worker request, including export and status. Control RPCs have an eight-second response deadline; worker deadlines trigger outcome queries. Export shares the active task controls and suppresses duplicate submissions. A fresh document's hello carries a host token injected into its embedded script. A native generation-bound 15-second boot watchdog and required-resource error handling cover cases where JavaScript never executes. Modern runtimes use request-source-kind filtering for all resource sources; `E_NOINTERFACE` selects the pinned SDK's legacy filter with the same deny policy.

Only the embedded `https://app.kndbgx.local/index.html` document can send accepted RPC. Schema, origin, method, fields, string IDs, target/window generations, replay and size are checked. External resources/navigation, frames, downloads, arbitrary popups and permissions are denied. Release developer tools are disabled. Untrusted output uses text rendering.

Floating Inspect uses an owned native tool window and a second controller in the same WebView2 environment. Only the main WebView can request the exact `about:blank#kndbgx-inspect-<token>` popup. The host completes its NewWindowRequested deferral after controller setup; the popup inherits the main origin and receives only the embedded stylesheet. Web messages, host objects, dialogs, downloads, frames, further popups and external navigation remain disabled in the child. The frontend adopts the existing Inspect elements into this document and returns them on Dock, keeping one application state, one bridge and one engine coordinator. Owner-document lookup, selection, clipboard fallback and mirrored event handling preserve input and keyboard behavior. A token-bound `inspectionWindow` control RPC changes native visibility/focus without entering the engine worker. Native X hides the child and notifies the main document. Main close/reopen hides/restores both controllers; explicit shutdown and document recovery close the child and finish pending deferrals. Generation checks reject late controller callbacks, and controller teardown is deferred beyond active COM callbacks. Popup or stylesheet readiness failure leaves the panel docked. Modal and palette display temporarily hide and disable floating Inspect, raise the main window, then restore the panel and focus. Floating placement lasts for the current document; a recreated document starts docked.

Each inspection view can also float independently. The host admits only four named slots (`processes`, `memory`, `disassembly`, `registers`) through `about:blank#kndbgx-inspect-<view>-<token>`, mutually exclusive with the grouped slot. Each slot owns its window, controller, deferral, token, generation and visibility epoch. DOM nodes and application state remain shared with the main document. Tabs retain a Show/Dock placeholder; native X docks only that individual view, while Dock all restores every view. Main hide/show, overlays, pending-open cancellation and shutdown apply to every slot. The shared clipboard menu/fallback follows its source document and returns safely before that document closes. Detached layout is document-local and recreated workspaces start docked.

Visibility controls also carry a native visibility epoch. Frame close advances it; queued show/restore/hide requests with an older epoch cannot undo that close. Notices and stale-control replies reconcile only newer epochs, and every frontend visibility change invalidates older rollback callbacks. Overlay opening cancels pending Float initialization; a failed hide/restore returns the same panel to the main document. Clipboard fallback chooses the source grid's current visible document when the promise rejects. Native focus acknowledgements are bound to the floating instance and the user-interaction counter, so later keyboard/pointer activity or docking wins, including docking another independently floating view. Tabs remove cross-document aria-controls references while floating and restore them on Dock.

The UI locks during classification/planning, binds approval to server IDs, waits for every preview chunk, prevents duplicate submission, and cancels obsolete streams. Korean composition events and keyCode 229 cannot submit a command. Dialog focus is trapped/restored and background content is inert. Large tables use bounded DOM pages; forced colors and small viewports have dedicated styles.

Initialization is a checked transaction across asynchronous completion, settings and mandatory policy subscriptions. The embedded page is ready only after successful navigation and a fresh handshake. Callback/control generations reject late events. COM operations may dispatch sent window messages, so retry and teardown are deferred until active callbacks/operations return. GPU/utility failures preserve surviving documents; browser/main renderer loss revokes pending work and plans and requires recreation without replay.

## Release checks

Build settings enable SDL, stack cookies, CFG, ASLR, NX, high-entropy VA, CET compatibility and EH continuation metadata. Release checks inspect the resulting PE and matching PDB rather than relying only on project flags. Dependency locks allow only verified text line-ending normalization. The package has source/artifact hashes, support documentation and an SBOM.

Optional separate-process UI and TTD/Replay SDK adapters are disabled. Kernel and cross-host support remains Experimental pending tests on the corresponding targets. See [SUPPORT.md](docs/SUPPORT.md) and [VALIDATION.md](docs/VALIDATION.md).
