# Command reference

Generated by `tools/release.py docs` from the compiled CommandSpec registry.

Use `!kndbgx <command>` in WinDbg and `<command>` in the KNDbgX UI. Registered names and aliases retain KNDbgX grammar and per-operation approval. Unregistered UI input is forwarded directly to WinDbg; the CLI and background jobs require explicit `raw --ack-effects`. There is no global write switch. See [UX.md](UX.md) for forwarding behavior and output handling.
Support labels apply only within the tested configurations in [SUPPORT.md](SUPPORT.md).

Session availability (Modes), together with Capability and the handler's checks:

- `Any` — no dump/live restriction from this mode field; Capability still determines whether an engine or target is required.
- `DumpAndLive` — permits dumps and live kernel sessions. It does not by itself require a kernel target; commands with Target or StoppedTarget capability can also support user-mode targets.
- `LiveKernel` — refuses dump sessions and permits live kernel sessions. KernelX64 capability requires a kernel target; commands with StoppedTarget capability can also support live user-mode targets. Handler restrictions still apply, including local-KD mutation refusals.
- `LiveKernelLocal` — live-only and additionally restricted to local kernel debugging: these collectors compare debugger-host data with the target and refuse remote live targets with the host-local message.

## Help and completion

`help ui` (or `:help` in the UI) describes the workspace. `help <command-or-alias>` shows grammar, aliases, options and session availability.
Inspect contains Processes, Memory, Disassembly and Registers. Each view can Float independently, including from the floating group; Dock or its native close button returns it, and Dock all restores every view. The group and individual windows can coexist. Drag a native title bar onto the workspace or group drop guide to dock it. See [Floating inspection windows](UX.md#floating-inspection-windows).
`registers [name]` (alias `r`) reads the debugger's current register context. The command produces a snapshot in Results. Register browsing uses [Inspect > Registers](UX.md#registers-tab), which keeps a separate retained view, refreshes while visible on new stopped contexts and shows changed values and raw vector bytes. Process selection or address-space attachment does not switch the current thread/CPU register context.
UI completion uses this registry for names, required-argument templates, help operands, selector prefixes and options. Loaded-symbol suggestions require a current stopped context and do not reload PDBs. Completion edits drafts without execution; enter PID and path values explicitly. See [UX.md](UX.md#find-and-run-commands) for input controls and [Recent address lists](UX.md#memory-tab) for explicit current-context reads.

## Omitted targets

`!threads` reads the current ETHREAD and its owning process, which may differ from the attached process. `!threads <process>` lists that process's threads; `!threads ethread:ADDRESS` selects one corroborated thread.
`!process` reads the current debugger process; `!process 0` and `!dml_proc` enumerate all processes. `!vad` uses the current process, including when only options are supplied.
On remote live x64 kernels, `!hiddenproc` compares target `PsActiveProcessHead` with target `PspCidTable`. CID entries must corroborate the System process and match each PID to its EPROCESS. Differences are re-observation candidates, including process creation/teardown, not proof of hiding. An incomplete view cannot establish absence; objects removed from both views remain invisible to this comparison. Verified local KD retains the Toolhelp comparison.
`!handles` reads target process handle tables on remote live x64 kernels; `/owner-pid` narrows the scan and `/target-pid` filters process-object handles. Matched metadata, verified Process types and the owner's PID are required. Unreadable owner tables become scoped gaps while other owners are inspected. Scans are bounded: CID comparison allows 120 seconds, handle enumeration 30 seconds, and cancellation remains available. Partial results never imply a complete inventory. Verified local KD retains its host handle snapshot.
`!vad` can read an untyped public `MmProtectToValue` symbol only when all 32 observed entries match the supported PAGE_* mapping; missing, short or unfamiliar mappings remain Unknown. `/limit` caps console display, not traversal or stored rows.
`!token` reads the current thread's impersonation token when active, otherwise the current process primary token. An explicit process selector always reads its primary token. Missing impersonation metadata is Unavailable, not a primary-token fallback.
`!ci` requires verified local kernel context unless `/host` explicitly selects the debugger host. Its `Any` registry mode allows this explicit host query without a target; it never substitutes host CI/HVCI state for a remote target or dump. `!hv` also labels its host CPUID separately from debuggee CR4; hardware features require the advertised leaf range and the vendor-neutral Hv#1 interface.
Virtual memory displays (`db`/`dw`/`dd`/`dq`/`dc`/`dds`/`dqs`/`da`/`du`) continue after the last successful display, initially at the current instruction. Physical displays have a separate cursor, initially zero. `u` has an independent continuation cursor. Cursors are invalidated by target, stop, context or DTB changes; native WinDbg display cursors are separate.
`L<count>` alone uses the default address. `da` counts bytes and `du` counts UTF-16 code units, stopping earlier at a terminator. `source` without an address uses the current instruction.
`ln` and `uf` without an address use the current instruction, independently of the `u` continuation cursor. Unreadable or invalid instructions are not decoded rows; failed `u` commands preserve the previous cursor. Native `uf` text remains Partial because complete function coverage is unverified; use Details / View output to inspect it.
Object/file/write operands without a defined current target stay required, including `!drvobj`, `!devstack`, `irp`, exports and mutation plans. `procctx` overrides translation DTB only; it does not select the current EPROCESS/ETHREAD.

## Limits

Memory change plans are limited to 64 KiB, expire after 60 seconds, and can be used only once. Physical writes are disabled.
`debug-plan` supports breakpoint-add/remove/enable/disable and go/step-into/step-over; `debug-approve` requires its own token.
Snapshots use new directories. Snapshot v2 collectorVersion 3 includes unloaded-driver events keyed by verified name/range/unload time, independently of ring position. Missing collections in older bundles remain Partial. `!diff` requires `/cross-session` for different session identities; unload events remain incomparable across sessions even with this override. Imported missing fields remain Unknown. Added/Removed requires complete coverage and known identities for every row in that collection.
`results` and `result-read` access the shared store: 16 unpinned recent results plus up to 128 protected open UI-tab results within 64 MiB. Closing a result tab or destroying its UI document releases protection; ordinary window closing retains it. Save results before eviction or DLL unload.
`model publish <id> [row-offset] [finding-offset]` copies at most 128 rows and 128 findings to `Debugger.Models.KNDbgX`. Arrays use Count and r0, r1, ... keys.
`result-export <id> <path>` saves the complete stored result atomically; oversized page records link to the original data for export.
Data Model values are copied into host memory and remain readable after extension unload; viewing them does not read the target.
KNDbgX's `history` command and bookmarks keep the original session and stop epoch. `back` and `forward` display saved results without reading a new target. The inspection address inputs' Recent lists are separate: selecting an entry explicitly reads its expression in the current context.
`source` delegates a numeric address to the host source listing. Missing symbols/source produce Unavailable.
